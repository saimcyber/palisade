Confirmed on this rebuild specifically (not just "the cluster came
up"):
- The gateway's deployed image digest is sha256:f1ef281b..., the
  digest carrying both chaos-day fixes (RemoteProtocolError,
  RedisError) - the fixes are in the chart's committed values, not
  something that only existed on the previous cluster's live state.
- All 7 Prometheus alert rules loaded, including
  PalisadeGPUMemoryPressure (added after chaos day found the gap) -
  no sync-lag this time, since the rule was already in the ConfigMap
  from the first apply rather than added to a running cluster
  mid-session (see deploy/observability/prometheus-config.yaml's own
  header comment for that separate, real gotcha found earlier in the
  session).
- A real end-to-end request against the rebuilt stack: POST
  /v1/chat/completions, HTTP 200, a real generated completion
  ("OK, that's a"), not a cached or stubbed response.

This is the actual verification this project's CLAUDE.md calls for -
"Test from scratch, not incrementally" - run after every milestone's
substantive work, not assumed from a cluster that has been running and
accumulating live-patched state across an entire chaos day.
