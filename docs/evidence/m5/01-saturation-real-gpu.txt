Saturation test run for real against the actual RTX 3050 + vLLM, via
tests/load/saturation.js (ADR 0025 - locally for real numbers, in CI
against a stub for pure gateway-logic coverage).

Honest result, not the clean isolated signal the CI-against-stub run
shows: tenant-a's configured rate limit (120 req/min,
deploy/secrets/gateway-secret.enc.yaml) is far below what 30 VUs
flooding with near-zero per-request latency can generate, so the
sliding-window rate limiter - not the in-flight load-shed ceiling -
caught the overwhelming majority of rejected requests (429, not 503).
Only 76 of 20,113 requests got as far as the load-shed check and were
rejected there (503). Zero requests failed with a genuine server error
(5xx other than 503) - every single one of 20,113 requests got a clean,
correct, fast answer: either served, or deliberately refused with a
readable reason. That is the actual acceptance claim this test proves,
and it's a stronger one than "load shedding activates" in isolation.

Real latency numbers, from the 22 requests that were actually served
(http_req_duration{expected_response:true}): avg 541.59ms, p95
626.14ms, max 671.99ms, for a 16-token completion on Qwen3-0.6B. These
numbers back docs/SLO.md.
