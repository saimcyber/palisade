# M3 acceptance (part 2): an unsigned image is refused by the cluster, with a readable reason
#
# The unsigned image is the real gateway image plus one extra LABEL layer, pushed to
# ghcr.io/saimcyber/palisade-gateway:unsigned-demo with a personal registry token -
# i.e. what a stolen registry credential can do. It cannot be signed as this repo's
# GitHub Actions workflow identity, which is the only signer Kyverno accepts.
#
# Both pods below are the gateway's own rendered pod spec, byte-for-byte, differing ONLY in
# the image digest - so every baseline rule (non-root, drop ALL, read-only root, limits)
# passes, and the signature is the only thing that can decide the outcome.

## Diff between the two pod specs
    6c6
    <   name: gateway-signed
    ---
    >   name: gateway-unsigned
    17c17
    <     image: ghcr.io/saimcyber/palisade-gateway@sha256:d8a0af80253621922cb9d320691a2ce74a027d6ba5fadc67ff2ea6acfa5b891e
    ---
    >     image: ghcr.io/saimcyber/palisade-gateway@sha256:c07cca104d7d80068cb9a030e9c63e7a2a6c129e442a839e127b1eadfb36fba6

## 1. Positive control - signed digest from CI (server-side dry run: full admission chain, nothing persisted)
$ kubectl apply --dry-run=server -f signed-pod.yaml
pod/gateway-signed created (server dry run)

## 2. The unsigned digest - a real apply
$ kubectl apply -f unsigned-pod.yaml
Error from server: error when creating "/tmp/unsigned-pod.yaml": admission webhook "mutate.kyverno.svc-fail" denied the request:

resource Pod/palisade/gateway-unsigned was blocked due to the following policies

verify-palisade-image-signatures:
  verify-gateway-signature: 'failed to verify image ghcr.io/saimcyber/palisade-gateway@sha256:c07cca104d7d80068cb9a030e9c63e7a2a6c129e442a839e127b1eadfb36fba6: .attestors[0].entries[0].keyless: sigstore bundle verification failed: no matching signatures found'
[exit code 1]

$ kubectl -n palisade get pod gateway-unsigned
Error from server (NotFound): pods "gateway-unsigned" not found
